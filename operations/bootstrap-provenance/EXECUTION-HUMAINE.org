* Objet et préconditions

Cette opération importe un paquet d'observation inerte puis lance une seule
commande sans argument. L'administrateur humain utilise son canal existant.
Spectre vérifie les fichiers publics et prépare le geste ; aucun shell général
ou root du VPS n'est délégué à un agent. Aucun =installer.py= n'est exécuté.

L'observation demande uniquement =nixos-version --configuration-revision= et
=nixos-version --revision= sous le compte existant =mrjam-inventory=, dans une
unité transitoire confinée et bornée. Elle ne lit aucun fichier de configuration
local, donnée métier, secret, journal ou sauvegarde. Elle retourne seulement des
SHA Git complets ou des codes inconnus après filtrage côté VPS.

La revue Spectre de cette extension et de ses preuves précède le geste humain.
Le compte doit exister et les dépendances de la première remise doivent déjà
être installées. Ce delta ne remplace pas une fermeture absente : en cas de
dépendance manquante, arrêter et rapporter le code fermé, sans fetch, relâchement
de confiance Nix ou modification de service. Aucun import sur Spectre n'est requis.

* Vérifications sur Spectre

Vérifier l'empreinte de l'archive publique avant extraction dans un nouveau
dossier. Vérifier les membres réguliers, sans lien, chemin absolu ou traversée,
puis toutes les entrées de =SHA256SUMS=. Ne jamais remplacer une attente pour
obtenir un succès. Depuis le dossier extrait :

#+begin_src bash
sha256sum --check --strict SHA256SUMS
python3 -I -S verify_delivery.py --transfer-directory .
#+end_src

La deuxième commande doit rendre =DELIVERY_VALID=. Aucun import dans le daemon
de Spectre, aucune lecture de clé privée et aucun accès de production ne sont
nécessaires à ces vérifications et à la revue du code.

* Commandes fixes de l'administrateur sur le VPS

Transférer seulement cette remise publique dans un nouveau dossier sous contrôle
de l'administrateur. Le conserver non modifiable par les agents et les comptes
non privilégiés pendant les vérifications et l'import. Depuis ce dossier et
la session humaine d'administration existante, exécuter le bloc ci-dessous.
Chaque étape doit réussir avant la suivante. Les fichiers de sortie ne sont
pas écrasés ; utiliser un dossier nouveau pour une reprise explicitement revue.

La comparaison doit rendre =STORE_METADATA_MATCH=. L'option =--no-trust= est
limitée au contrôle de contenu : elle ne modifie aucune politique de confiance
persistante et ne désactive pas les exigences de signature de l'import.
=--extra-experimental-features nix-command= est explicite sur les deux commandes
qui le nécessitent ; ne pas modifier =nix.conf= pour les faire passer.

Le programme immuable refuse arguments, copie mutable, unité préexistante ou
protection indisponible. Il n'émet aucun JSON partiel en cas de refus. Ne pas
arrêter une unité préexistante, agrandir un budget ou utiliser un autre programme
pour contourner une erreur. L'observation est la seule invocation du paquet.

* Retour fermé et fin

Après succès, transférer seulement =provenance-v1.json= à Spectre. Revalider :

#+begin_src bash
python3 -I -S filter/probe/validate_report.py < provenance-v1.json
#+end_src

Ce filtre ne fait aucune collecte. Il refuse champs supplémentaires, types,
SHA incomplet, autorité différente et =state_version= non nul. Après succès,
retourner uniquement ce JSON à Cloud. Une valeur =unknown= valide reste inconnue.
En cas d'échec du filtre local, retourner seulement :
={"step":"spectre_validation","code":"REPORT_REFUSED"}=.

En cas d'échec humain, retourner uniquement le dernier objet fermé généré par
le bloc (étape, =COMMAND_FAILED=, code numérique). Ne pas transmettre les
sorties précédentes, les chemins importés, le JSON de fermeture ou un journal.
Un fichier vide ou un succès d'import seul n'est pas un rapport d'observation.
