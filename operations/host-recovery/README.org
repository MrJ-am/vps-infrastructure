* Analyse reproductible, sans évaluation du code reçu

=normalize_sources.py= vérifie le manifeste épinglé et chaque fichier avant
lecture de sa syntaxe. Il refuse les liens et les sorties existantes. Il crée
un nouvel arbre d'analyse sans modifier l'original. Ses 35 substitutions,
réparties dans 21 fichiers, remplacent les chemins source absolus présents par
des chemins relatifs ancrés au fichier. Les chaînes deviennent =toString= d'un
chemin ancré ; un simple texte relatif aurait changé leur sens.

Les chemins de données, scripts incorporés, interpolations et entrées absentes
ne sont pas exécutés ou complétés. Une présence de répertoire signifie seulement
qu'une partie a été remise. La normalisation ne prouve pas l'équivalence de
l'assemblage et le résultat reste =activatable=false=.

=analyze.py= classe 333 références littérales, 22 références de recherche Nix
non verrouillées et 15 références de répertoires partiels. Les 114 cibles
littérales non remises ne sont pas 114 imports actifs manquants. Notamment :

- les défauts Audition et =forgejoKanidmApi= signalés dans le relais sont
  remplacés par les arguments de leurs appels ;
- =modulesPath + "/profiles/qemu-guest.nix"= désigne le profil du nixpkgs
  sélectionné, pas un fichier VPS absent sous =/profiles= ;
- les JSON, archives, branches inactives et chemins d'exécution ne sont pas
  récupérés pour « fermer » artificiellement le graphe.

34 fichiers remis sont identiques octet pour octet à du code de
=reference-nixos/=. Ce rapprochement ne transforme pas un identifiant de
répertoire en commit authentifié. =verify_profile.py= vérifie séparément douze
faits du socle matériel/réseau contre les littéraux Nix reçus, sans import,
appel de fonction ou lecture d'une dépendance. Il refuse les expressions
dynamiques. Les résultats détaillés sont versionnés sous =results/=.

* Reproduction dans Cloud

CPython 3.12.14 a exécuté l'analyse ; les deux roues Linux x86_64 sont épinglées
par version, ABI, URL, longueur et SHA-256 dans =parser.lock.json= et
=parser-requirements.txt=. Installer ces seules dépendances dans un répertoire
local dédié, jamais dans le VPS :

#+begin_src bash
python3 -m pip install --no-deps --require-hashes --target /tmp/mrjam-source-parser \
  -r operations/host-recovery/parser-requirements.txt
export PYTHONPATH=/tmp/mrjam-source-parser
python3 -B -m unittest discover -s operations/host-recovery/tests -v
python3 -B operations/host-recovery/normalize_sources.py \
  --extracted operations/received/20261101/vps-reviewed-sources/extracted \
  --review-sha256 f00c3fe7eb794e4e1e4b1518b437b7d44faa6804577428b332a889a05fc095f8 \
  --output /tmp/mrjam-vps-normalized-new
python3 -B operations/host-recovery/analyze.py \
  --extracted operations/received/20261101/vps-reviewed-sources/extracted \
  --review-sha256 f00c3fe7eb794e4e1e4b1518b437b7d44faa6804577428b332a889a05fc095f8 \
  --reference-code reference-nixos
python3 -B operations/host-recovery/verify_profile.py \
  --extracted operations/received/20261101/vps-reviewed-sources/extracted \
  --review-sha256 f00c3fe7eb794e4e1e4b1518b437b7d44faa6804577428b332a889a05fc095f8 \
  --profile operations/hosts/mrjam-vps/received-profile.json
