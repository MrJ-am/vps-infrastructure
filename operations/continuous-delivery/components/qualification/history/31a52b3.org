* Défaut SQL restant : commentaires imbriqués

Le nettoyage regex de =migrations.validate_sql()= ne suit pas l'imbrication des
commentaires PostgreSQL. Ce texte est accepté par le chargeur et le constructeur
de transaction du candidat :

#+begin_src sql
/* outer /* inner */ ' */ END;
INSERT INTO synthetic_qualification_records VALUES (1); SELECT 'ok';
#+end_src

Avec =checks.sql= contenant =SELECT 1/0;=, PostgreSQL interprète le commentaire
imbriqué correctement puis exécute =END;= hors commentaire. L'insertion suivante
est autocommit : une ligne persiste malgré l'échec du contrôle. Le test
=test_nested_comment_with_quote_cannot_hide_END_and_persist_data= échoue sur
=1 != 0=, avec le vrai PostgreSQL jetable dans le sandbox Nix.

Le premier =/* ... */= non gourmand de la regex se termine au commentaire
intérieur. L'apostrophe encore située dans le commentaire extérieur est ensuite
prise pour le début d'un littéral et masque le vrai =END;= dans la vue nettoyée.
Il faut reconnaître correctement les commentaires imbriqués et les états
lexicaux SQL pour éviter cette divergence. Le test reste actif, sans expected
failure ni suppression de l'assertion de non-persistance.

métier. Les frontières OS/systemd, les générations et les processus des slots
