#+title: Références privées des travailleurs natifs

Ce lot adapte les formats locaux hérités et observe les capacités Kanidm sans
mutation. Il ne lit aucun secret réel pendant sa construction ou ses tests.
Les binaires Rust gelés restent inchangés. Les références et hashes des sources
figurent dans =provenance.json= ; les résultats de construction sont distincts
de la qualification indépendante des unités.

* Adaptateur hors ligne

=mrjam-worker-credentials-adapt= ne prend aucun argument et exige root. Ses trois
entrées sont fixées sous =/run/mrjam-worker-credential-adaptation/= :
=proton-smtp.json=, =cycle.json= et =fermeture-hook.secret=. Le répertoire doit
être root:root 0700 ; ses seuls fichiers sont réguliers, root:root 0440, à lien
unique, sur un montage en lecture seule. Aucun chemin transmis, lien symbolique,
fichier supplémentaire ou configuration d'environnement n'est accepté.

=proton-smtp.json= possède les sept champs du lecteur Lisp et du lecteur Rust :
=host=, =port=, =username=, =password=, =from_address=, =starttls_required= et
=certificate_verification=. Le relais reste =smtp.protonmail.ch:587= avec
STARTTLS et vérification du certificat obligatoires. Les valeurs sont conservées
dans un JSON compact ; aucune adresse ni aucun mot de passe n'est normalisé.

=cycle.json= fournit exclusivement =recipient_age= et =adresse_exploitant=.
Le hook conserve sa valeur historique de 43 caractères ASCII ; seuls les blancs
de bord que retirait déjà le lecteur Lisp sont retirés. Le secret d'approbation
est distinct : 32 octets CSPRNG encodés en base64url sans remplissage, créé une
seule fois et conservé lors des reprises. Aucun jeton Kanidm n'est créé ou copié
par cet adaptateur.

La génération publiée est =/var/lib/mrjam-worker-credentials/v1/=, répertoire
root 0700 avec six fichiers root 0600 :

| Fichier | Référence LoadCredential des consommateurs |
|---------+-------------------------------------------|
| smtp.json | smtp pour admission, cycle et archive, y compris initialize |
| recipient | recipient pour archive et archive-initialize |
| closure | closure pour admission ; admissions pour closure et replay |
| approval | approval pour admission et son raccord authentifié autorisé |
| archive.json | configuration pour mrjam-vision-archive.service |
| archive-initialize.json | configuration pour mrjam-vision-archive-initialize.service |

Les deux JSON archive contiennent le recipient age extrait localement. Il ne
figure pas dans la forge ni dans le store. Seuls le nom de la base journal et le
programme age épinglé sont des paramètres publics de construction. Chaque JSON
conserve les chemins =smtp_file= et =recipient_file= exacts de son unité.

Le module =operations/nixos/mrjam-vision-archive.nix= expose les deux références
=configurationCredentialFile= et =initializeConfigurationCredentialFile=.
L'utilisation de ces références exige =ageRecipient=null=. L'ancien mode public
reste possible si les deux références privées sont absentes. Aucun service ni
timer ne démarre implicitement.

La publication verrouille le parent privé, prépare une génération complète,
synchronise les fichiers puis publie le répertoire. Une génération existante
identique n'est pas réécrite et son approbation ne change pas. Une interruption
entre fichiers reprend les fichiers manquants ; un fichier partiel, différent,
public ou lié impose un refus sans remplacement. Limites d'entrée : 64 Kio par
JSON, 128 octets pour le hook ; chaque sortie est inférieure à 8192 octets.
L'unité doit être sans réseau, avec =LimitCORE=0= et une échéance courte.

* Probe Kanidm sans mutation

=mrjam-kanidm-capability-probe= ne prend aucun argument et exige root. Sous
=/run/mrjam-kanidm-capability-probe/=, les seules entrées permises sont
=admission=, =cycle= et =replay=. Elles peuvent manquer pour constater leur
absence. Le répertoire est root 0700 ; les fichiers présents sont root:root
0440, à lien unique, montés en lecture seule et limités à 4096 octets comme le
lecteur des travailleurs. Le programme ne cherche aucun autre fichier secret.

Il joint uniquement =127.0.0.1:8443= en HTTPS, SNI et Host =log.mrj.am=, avec la
CA publique épinglée au build. Aucun proxy, redirect ou repli TLS n'est utilisé.
Il effectue au maximum 21 GET : =/v1/self= pour chaque capacité présente, puis
les seuls attributs =account_expire=, =account_valid_from= et =passkeys= des
comptes de service intégrés =admin= et =idm_admin= lorsque l'identité de service
est reconnue. Il ne liste ni personnes ni comptes, ne lit aucun jeton en réponse
et ne décode aucun JWT. Chaque réponse est bornée à 64 Kio ; une unité doit
imposer =TimeoutStartSec=60=, réseau restreint au loopback et =LimitCORE=0=.

La réponse est un objet fermé composé d'une version et de booléens : présence,
distinction des trois jetons, identité de service attendue, groupes visibles,
possibilité de constater le préétat administratif et état désactivé constaté.
Aucun nom lu, UUID, date, groupe brut, claim, token ou erreur distante n'est
émis. =write_authorization_proved=false= reste toujours explicite : une lecture
de sa propre identité et de ses groupes ne prouve pas le droit d'effacer une
personne. Un attribut caché ou null n'autorise aucune récupération.

Le probe n'est pas une autorisation de provisionner. Le rôle de sa sortie est de
constater les capacités réellement disponibles avant de choisir la procédure
administrative décrite dans =PROVISIONING.org=.

La variante =probe-standalone.py= permet l'observation avant bascule sans montage
ni copie supplémentaire. Elle est transmise exactement sur stdin à =python -I -S
-=, avec la CA publique embarquée et hashée. Elle ouvre uniquement
=/var/lib/mrjam-identite/kanidm-admission.token=, =kanidm-cycle.token= et
=kanidm-replay.token=. Chaque fichier présent doit être root 0600 à lien unique ;
chaque composant de chemin est ouvert sans suivre de lien symbolique. Aucun
répertoire n'est parcouru pour découvrir des secrets. L'alarme est de 120 secondes
et =RLIMIT_CORE=(0,0)= est imposé avant toute lecture de token.
=generate_standalone.py= extrait les fonctions qualifiées sans import de fichier
au runtime ; =standalone-source.json= fixe les hashes. Les cinq tests du script
final vérifient également l'exécution stdin depuis un répertoire piégé.

La forme =/v1/self= attendue a été confirmée indépendamment sur Kanidm 1.11.2 avec
un API token synthétique : =youare.attrs=, nom exact, classe =service_account=,
UUID unique minuscule et =memberof= sous forme de SPN =nom@log.mrj.am=. Cette
observation n'a transmis ni token, ni claim, ni UUID.

* Validation

L'adaptateur a 17 tests d'auteur ; le probe en a 8, incluant un vrai serveur TLS
inventé, les refus de CA et de nom, la fermeture des chemins HTTP et la rédaction
fermée des erreurs. Les tests ne se connectent qu'à des fixtures locales.
=module-evaluation.nix= vérifie le mode privé et ses refus ; le test historique
du module reste vert. Le passage des JSON privés par LoadCredential puis le
binaire archive gelé est validé par =operations/identity/mail-result-001.json=.
La nouvelle opération d'adaptation elle-même doit encore être qualifiée
indépendamment avant activation. Aucune exécution de production n'a lieu dans
ce lot.
