* Travaux concrets et limite de compatibilité

Le module [[file:../nixos/mrjam-system-provenance.nix][mrjam-system-provenance.nix]] ajoute, lorsqu'il sera explicitement
sélectionné dans une génération revue, la révision complète à
=system.configurationRevision= et un document fermé sous
=/etc/mrjam/system-provenance.json=. Il exige des références complètes,
la concordance du pin nixpkgs et une valeur de compatibilité déjà établie.
Il ne fixe ni ne relève =stateVersion= ; un désaccord est refusé.

Le document décrit les entrées de code, sans secret, donnée ni identité NAR
de sa propre sortie : cette dernière créerait une boucle de hachage. Les
empreintes de la génération restent dans le manifeste de livraison externe.
L'autorité déclarée reste =declared_build_metadata=, jamais une approbation.
Le module est désactivé dans la composition VPS préparatoire.

Les 33 contrôles de ce module passent avec chacun des deux nixpkgs. Les
21 contrôles de composition VPS incluent maintenant le retour reçu et vérifient
que les inconnues n'ont pas été remplacées. La matrice détaillée et les reçus
de construction sont dans [[file:../compatibility/README.org][le dossier de compatibilité]].

La matrice sur la base observée est globalement NON compatible : le paquet de
préparation Forgejo exige 17.0.1 et cette base fournit 16.0.3. Le contrôle de
version refuse la substitution. Il n'est ni retiré ni affaibli ; les builds
actifs Forgejo/runner/Kanidm restent inconnus, et leur migration doit être
qualifiée séparément. Le succès des autres modules n'efface pas ce blocage.

* Preuve manquante et prochain relais

La recherche locale de checkout sur Spectre et les observations V1, V2 et
provenance sont terminées. Les répéter ne restituera pas une révision qui
n'est pas fournie par ce canal. La prochaine pièce utile est une référence
du code de la configuration réellement utilisée : dépôt, commit et point
d'entrée, avec les éventuels ajouts non versionnés identifiés côté opérateur.

Le [[file:RECUPERATION-SOURCES-SPECTRE.txt][prompt de récupération des références]] prépare cette recherche pour
l'administrateur humain, à partir du point d'entrée NixOS connu. Il ne délègue
aucun shell de production à un agent et ne demande aucun transfert de données,
secret, sauvegarde ou configuration brute. Seuls des éléments de code relus
peuvent ensuite être proposés sur une branche de travail.

Les autres blocages du [[file:../dossier-deploiement.org][dossier de déploiement]] restent ouverts : génération
complète, adoption effective, identité, versions actives, isolation/quotas,
autorité des règles, sauvegarde/restauration et bascule/retour. Aucune activation
de production n'a eu lieu dans cette intégration.
