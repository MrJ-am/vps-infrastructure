* Objet et opérateur

Cette opération humaine importe un paquet préconstruit puis lance une seule
observation filtrée. Elle n'active aucune génération NixOS et ne déploie aucune
application. Elle ne donne aucun accès root, shell, SQL ou données à un agent.
Le compte mrjam-inventory et l'accès SSH V1 restent inchangés.

L'administrateur utilise son canal existant pour transférer la remise sur le
VPS puis exécuter les commandes fixes ci-dessous. Codex sur Spectre peut
vérifier les fichiers publics localement et préparer ce geste ; il n'obtient
pas un shell de production pour l'effectuer. Aucun installer.py n'est utilisé.

python3 verify_delivery.py --transfer-directory .

* Commandes fixes de l'administrateur sur le VPS

Ces commandes s'exécutent dans le dossier de remise transféré, depuis la
session d'administration humaine existante. Chaque commande doit réussir
avant la suivante. Le script de vérification est celui de la remise revue.
Les fichiers de transfert doivent rester sous contrôle de l'administrateur
pendant la vérification et l'import ; ils ne sont pas un canal d'écriture
accordé aux agents sur le VPS.

#+begin_src bash
set -euo pipefail
test "$(id -u)" -eq 0
sha256sum --check SHA256SUMS
printf '%s\n' '81f3d750ef24577494019e6823492fe83c57f385a6c90dcda570b959eb42b1f6  mrjam-observe-adoption-v2.nix-export.gz' | sha256sum --check --strict -
gzip --decompress --stdout mrjam-observe-adoption-v2.nix-export.gz | nix-store --import > chemins-importes.txt
nix store verify --offline --no-trust --recursive /nix/store/25rzj9i3jv9f1878dwgkysnc454ndr84-mrjam-observe-adoption-v2
nix path-info --offline --json --recursive /nix/store/25rzj9i3jv9f1878dwgkysnc454ndr84-mrjam-observe-adoption-v2 > fermeture-installee.json
/nix/store/kp6p38x6zb21n7gdlnp9nsm2aagq7sg2-python3-3.13.17/bin/python3 -I -S verify_delivery.py --store-info fermeture-installee.json
/nix/store/25rzj9i3jv9f1878dwgkysnc454ndr84-mrjam-observe-adoption-v2/bin/mrjam-observe-adoption > adoption-v2.json
#+end_src

=--no-trust= désactive seulement le contrôle des signatures dans cette
vérification de contenu ; aucune politique de confiance persistante n'est
modifiée. Les empreintes attendues de tous les chemins sont comparées au
manifeste qualifié avant le lancement. La comparaison doit produire
=STORE_METADATA_MATCH=.

Le dernier programme n'accepte aucun argument. Il crée une unité transitoire
fixe sous le compte existant, avec limites de temps/mémoire/tâches, sans réseau,
et n'émet le JSON qu'après validation. Il refuse un compte absent, une unité
préexistante ou une protection indisponible. Ne pas contourner un refus.

* Retour et fin de l'opération

Transmettre uniquement =adoption-v2.json= après succès. En cas d'échec, transmettre
uniquement l'étape et le code fermé ; pas de journal brut ni sortie d'un service.
Ne pas relancer les inventaires V1 ou l'installateur pour compléter les champs.

La sortie conserve =unverified_observation=. Elle aidera à reprendre le compte,
les répertoires et les références de génération sans inventer leurs valeurs.
Elle ne fournit pas la configuration NixOS complète, stateVersion ou les builds
actifs de tous les services. Les décisions complémentaires resteront bornées.

Le paquet importé reste inerte dans le store après l'observation. Aucune bascule
de service ou de données n'ayant lieu, aucun retour applicatif n'est exécuté.
Ne pas lancer un garbage-collect global, effacer un compte ou modifier SSH pour
« nettoyer ». Le verrou temporaire root dans /run peut subsister jusqu'au reboot.
