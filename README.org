Rust reçoit actuellement le trafic applicatif du VPS. Les automatisations
de livraison ont été arrêtées à la demande de l'utilisateur. Leur arrêt
n'arrête pas les applications déjà en service. La présence d'un module Nix
ou d'une procédure dans ce dépôt ne signifie pas qu'il est activé.

* Documentation de préparation historique

Les paragraphes suivants décrivent les travaux préparatoires. Ils ne sont
pas un inventaire de la configuration actuellement exécutée. Pour l'état
observé et les limites connues, commencer par les deux guides ci-dessus.

La reprise déclarative du 30 octobre est dans
[[file:operations/dossier-deploiement.org][le dossier de revue et de déploiement]].
Le =flake.lock= épingle les dépendances ; le flake exporte les modules inertes,
paquets préparatoires et contrôles synthétiques. L'accès d'inventaire impératif
reçu de Spectre est repris dans un module proposé, avec adoption encore bloquée
par les faits et contrôles manquants. L'utilisateur confirme ce dépôt comme
source de vérité attendue du VPS ; l'alignement installé reste à établir.

- =environment/= : environnement de développement et vérifications locales.
- =operations/= : propositions bornées d'exploitation ; le module Rust NixOS
  reste désactivé et n'active aucun routage.
- =interface-log/= et =interface-audition/= : frontends Elm conservés.
- =reference-nixos/= : sources historiques des services tiers et de l'identité,
  non importées par l'environnement ; dépendances et limites y sont documentées.
- =reference-schemas/= et =reference-contracts/= : sources utiles à la reprise,
  sans migration automatique ni preuve de qualification actuelle.

Les propositions de règles canoniques Elm sont dans =mrjam-validation/review= ;
leur adoption protégée reste à réaliser.
Aucune copie de ces règles ni aucun workflow de déploiement n'est maintenu ici.
La forge cible reste =https://forge.mrj.am=. La poursuite de l'exploitation exige
la qualification et les accès bornés prévus par le mandat.
